# ENGIE360: ENGIE Netherlands CX demo

PowerConnect.AI concept demo for ENGIE Netherlands, structured like Hydro Mobile360: a **customer app** (`/app`, MijnENGIE as a phone app: sign-in, bottom tabs Home · Energy · Eva · Billing · Profile, Eva the scripted assistant, Net2Grid features) and a **staff app** (`/staff`, ENGIE Customer Service: dashboard, customer activity, Eva conversations, messages, Demo control panel, phone preview) linked live. Demo tools (presenter bar, Send to phone, phone preview) live only in the staff app. One Node server runs everything on one port (:3000): API, SQLite database, live events, web push, the frontend and a start page at `/`. Like Hydro Mobile360: the portal lives under `/app` (router basename; routes inside stay short, e.g. `/energy`), the staff app at `/staff`; `src/main.tsx` picks the app and moves old portal links under `/app`. All data is sample data. **It is built and working**; changes from here are iterations. Read `README.md` for screens and the demo script, `DEPLOY.md` for running and hosting, and `PLAN.md` for how it was built.

Sister project: `E:\hydro-one-ev-demo` (Hydro One). ENGIE360 borrows how that demo *works* (one server, live staff side, push, start page, Catalyst hosting), never its content. The assistant NLU, presenter mode, lint rules and test setup follow its patterns; look there before inventing something new.

## Layout

- `shared/contract.ts`: REST paths, request/response types and live (SSE) events. The only link between `src/` and `server/`.
- `server/`: `index.ts` (listens first, then loads), `app.ts` (API + Vite middleware in dev, `dist/` in prod), `routes.ts`, `store.ts` (demo state and operations, seeded from `src/data`), `db.ts` (node:sqlite JSON docs), `live.ts` (SSE hub), `push.ts` (web-push/VAPID), `startPage.ts`, `static.ts`.
- `src/brand.ts`: brand name, portal, assistant (`Eva`), partner names. Never hard-code "ENGIE", "MijnENGIE", "Eva", "Net2Grid" or "Stedin" elsewhere. (Net2Grid is no longer shown in the customer app at all.)
- `src/data/*`: seed/mock data, also used by the server. `src/lib/time.ts` holds the demo clock (`DEMO_NOW`, `DEMO_TZ` = Europe/Amsterdam). Use `zoned()` / `dayKey()`; never `getHours()` / `setDate()` on local time.
- `src/api/`: API client, `LiveProvider` (server state + SSE, falls back to local data without a server), `httpAssistant.ts` (Eva via the server), `push.ts`.
- `src/assistant/`: `nlu.ts` (pure matcher) → `intents.ts` (definitions, phrases, suggestions) → `answers.ts` (pure answers) → `mockProvider.ts`. UI in `ChatPanel.tsx`; portal session in `PortalAssistant.tsx` + `portalContext.ts`.
- `src/components/RailShell.tsx`: the staff app's Hydro-style shell (top bar, hover-widening icon rail, phone drawer); `ThemeMenu.tsx` (Dark/Light/Match system).
- `src/components/PhoneFrame.tsx` + `src/lib/frame.ts`: on screens ≥ 700 px wide, `/app` shows the customer app as a 430 px phone column on a navy page (an iframe of itself, like Hydro Mobile360), with the address bar kept in sync. The app's own layout is therefore always phone-size; e2e tests run it at 390 px.
- `src/staff/`: the staff app: `StaffApp.tsx` (RailShell layout + routes, presenter bar, activity banners), `pages/` (Dashboard, Customer, Activity, Conversations, Messages, Reports, Assistant, Audit, DemoPanel), `parts.tsx` + `board.tsx` (cards: needs attention, usage, cost, composer, outbox), `Bell.tsx`, `merge.ts` (merge fields), `kinds.ts`, `context.ts` (`useStaff()`), `useStaffData.ts`. Server side: `Store.attention()` (points + suggested message, open → contacted → done), the outbox (sent/scheduled messages; a 1 s timer in `routes.ts` sends due ones) `Store.askStaff()`, and the audit log (`Store.auditLog()`; every send/schedule/cancel/reset adds an entry and emits `audit:new`). The AI assistant page follows the Hydro layout (orb + chips, typewriter answers, pill composer, tool rail); its conversation lives in `useStaffAssistant.ts` in the layout so it survives navigation. Reports export through `src/lib/csv.ts`.
- **Customer base:** the staff app covers 1,248 customers, all with US names. One is live (`src/data/customer.ts`, Olivia Carter, id `C-2003418762`: the phone in the demo, with a real app, inbox and Eva chat); the other 1,247 are generated the same way on every start in `src/data/customers.ts`. `Store.customers()` (search, filter, 25 a page), `customerDetail(id)`, `portfolio()` (counts + attention queue), `feed()` (what customers did, across the base) and `simulate()` (a sample customer acts every `SIMULATE_MS`, default 6 s; emits `feed`). Messages go to the live customer, another customer (`customerId`) or a whole attention segment (`segment`); only the live customer gets a real inbox message, reads for everyone else are estimated in `Store.outbox()`. Pages: `pages/Dashboard.tsx` (portfolio; cards in `portfolio.tsx`), `pages/Customers.tsx`, `pages/Customer.tsx` at `/staff/customers/:id` (live data for the live customer, `scale.ts` for the rest; visits grouped by `visits.ts`).
- `src/assistant/staff.ts`: the scripted staff assistant (same matcher as Eva, own intents; spec in `staff.spec.ts`). `src/data/templates.ts`: staff message templates.
- `src/pages/`: customer app screens and `Login.tsx`; `src/components/Layout.tsx` is the customer phone-app shell (app bar, `.app-tabs`, Eva button). Sign-in state: `src/lib/session.ts`; the guards in `App.tsx` are components (`RequireSignIn`, `LoginRoute`) so they re-check on every navigation. `public/sw.js`: push service worker.
- `src/lib/`: i18n, theme, presenter script (5 steps), charging planner, live power simulation. `src/components/`: layout, UI kit, toasts, nav, charts, presenter bar, phone QR.
- Tests: Vitest `src/**/*.spec.ts` and `server/**/*.spec.ts`; Playwright `tests/e2e/` (starts its own full server on :5190).

## Rules

- **The customer app (`/app`) must read as a real production app.** The API and data are mock, but nothing the customer sees says so: no "demo", "sample data", "simulated", "prototype", "scripted" or "fictional" labels, and no partner names or badges (Net2Grid); say "we" instead. Demo tooling and demo wording belong in the staff app and the start page only. An e2e test in `portal.spec.ts` checks every customer screen for this.
- Eva is scripted on purpose: no LLM or network calls beyond our own server. Her footer is a production-style assistant notice, not a demo disclosure. New questions = keywords/intent in `intents.ts`, an answer in `answers.ts`, specs in `nlu.spec.ts` / `answers.spec.ts`. Every suggestion phrase must round-trip to its intent. Prefix exact-only keywords with `=` (`'=auto'` must not match "automatische").
- Contract changes go in `shared/contract.ts` first, then server and client.
- Every user-visible string is bilingual: `t('English', 'Nederlands')` in components, `{ en, nl }` (`Text`) in data.
- Colours come from the CSS tokens in `src/styles/global.css`; each has a light and a dark value (`:root[data-theme='dark']`). `--navy` is brand navy for surfaces, `--ink` is text. Charts take colours from `useTheme().chart`. Lato is bundled (`@fontsource/lato`); no external font or CDN requests.
- External systems are simulated (not labelled as such in the customer app, see above). No real customer, payment or ID data.
- TypeScript strict; touch targets ≥ 44 px; accessibility labels on icon-only buttons; no horizontal scroll at 390 px.
- Lint: ESLint flat config with React Compiler rules: no synchronous `setState` in an effect, no ref writes/reads during render, and a `.tsx` that exports a component exports nothing else.
- Hosting constraints the server relies on (keep them): open the port before loading anything (Catalyst kills apps not listening within 10 s); port from `X_ZOHO_CATALYST_LISTEN_PORT`, then `PORT`, then 3000; SSE streams end at 25 s on Catalyst (30 s proxy limit); one instance only.
- After changes: `npm run check` (typecheck + lint + unit tests), then `npm run e2e`.

## Commands

- `npm run dev`: everything on http://localhost:3000 with hot reload (start page at `/`). `start-demo.cmd`: install + build + start for Windows.
- `npm run build` / `npm start`: production on :3000. `npm run deploy:catalyst`: Docker image to Zoho Catalyst AppSail.
- Demo day: staff app on the laptop, customer app on a phone (QR on the start page or Demo control panel). Shift+P in the staff app for the presenter bar (N/B/1–5/R/Esc). Phone push needs HTTPS (hosted URL) or localhost.
- Use npm (global pnpm is broken on this machine). Port 5173 is often taken by another app; the server uses 3000.
